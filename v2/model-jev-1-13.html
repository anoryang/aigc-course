Jev 1.13

不是聊天模型，而是给软件做快速、结构化判断的 System One 模型。

模型定位

一句话理解：GPT / Claude 更像写作者，会生成一段文字；Jev 更像一个很聪明的判断开关，把状态读完后直接给出可被代码使用的选择、分数或概率。

通俗解释

  • 先把它和 GPT / Claude 分开看：传统聊天模型更像“输入 → 思考 / 生成 → 一段文字”；Jev 更像“State → Decision → Probability”。
  • 举个退款工单例子：State 是“信用卡被扣了两次，我要退款”；Question 是“这个请求属于什么类型？”；Options 可以是 refund / technical_support / sales / other；如果 refund 概率很高，代码就可以把它送到 refund_agent。
  • 所以 Jev 不是帮你写一句回复，而是帮系统回答一串小判断：route? retry? safe? relevant? correct? which tool? which agent? memory worth saving? need escalation?
  • 在 Agent 架构里，可以把 GPT = 慢思考，Jev = 快速判断 / 反射。LLM 只负责真正需要 reasoning 的部分，周围大量 decision 交给便宜、快速的 specialized model。
  • 但不要误解成“不会 hallucinate 就永远正确”。Jev 不会输出 schema 外的格式，但完全可能很自信地选错，所以 probability ≠ accuracy guarantee，生产里仍然要有 calibration、threshold 和 fallback。
  • 概率与置信度不是一回事：四个选项的最高概率若为 0.94，Choice 的 confidence 约为 0.92。Noul 的 0.94 表示“是”的概率，不附带单独的 confidence。
  • 上面的退款示例仅解释流程，不是实际调用结果。系统需要同时检查用户身份、退款规则和操作权限，再决定执行还是转人工。

模型特色

System OneChoice / Score / Noul不是聊天模型路由与复核

  • 一句话理解：它像一个 AI 版 if 判断，但能读懂自然语言里的语义。
  • State → Question → Decision：先给当前状态，再问一个具体问题，最后拿到结构化结果。
  • Choice / Score / Noul：分别对应多选一、按标准打分、判断某件事成立的概率。
  • 输出给软件用：Choice / Score 返回选择或分数、概率分布与 confidence；Noul 返回“是”的概率，没有单独的 confidence 字段。代码据此分流、排序或复核。
  • 结构化输出：答案按你定义的选项或评分等级返回；格式确定不代表判断一定正确。

使用边界

  • 不是聊天模型：它不负责写文章、写代码、做长推理，也不适合作为知识问答入口。
  • 每个问题要小而清楚：复杂判断拆成多个 Choice / Score / Noul；同一请求可以并行提交多个问题，再在代码里组合。
  • 数学、计数、日期比较这类精确计算应交给代码，Jev 只做语义判断。
  • 当前以英文效果最稳；中文或多语言业务需要用自己的数据测试阈值和置信度。
  • 早期访问与限额会变动，正式接入前以 TypeSafe 控制台与文档为准。
